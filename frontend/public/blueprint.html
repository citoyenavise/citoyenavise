🔄 Data Flow & Cas d'Usage

Flux d'Authentification (Magic Link)
1

Utilisateur demande un magic link

POST /api/v1/auth/request-login {email}

↓
2

Backend génère token + envoie email

EmailService.sendMagicLink() - Token JWT 15min TTL

↓
3

Utilisateur clique sur le lien

GET /verify?token=xyz - Redirige vers /complete-profile

↓
4

Complète son profil

POST /api/v1/auth/complete-profile {display_name, region}

↓
5

Reçoit JWT token d'accès

Stocké en localStorage - Utilisé pour requêtes protégées

Flux Création de Pétition
sequenceDiagram participant User as 👤 Utilisateur participant Frontend as 🎨 Frontend participant API as ⚙️ Backend participant DB as 🗄️ Database participant Email as 📧 Email Service User->>Frontend: Clique "Créer une pétition" Frontend->>Frontend: Affiche formulaire User->>Frontend: Remplir titre, description, cible User->>Frontend: Clique "Créer" Frontend->>API: POST /petitions {title, description, elu_id} API->>API: Valide JWT + données API->>API: Crée petition (status: draft) API->>DB: INSERT petitions DB->>API: Retourne petition_id API->>Frontend: 201 {petition_id, status} Frontend->>User: "Pétition créée en brouillon" User->>Frontend: Clique "Publier" Frontend->>API: POST /petitions/:id/publish API->>DB: UPDATE petitions SET status='published' API->>Email: Notifier followers Email->>Email: Envoyer emails API->>Frontend: 200 {status: published} Frontend->>User: "Pétition publiée!" style User fill:#667eea,color:#fff style Frontend fill:#764ba2,color:#fff style API fill:#f093fb,color:#fff style DB fill:#4facfe,color:#fff style Email fill:#43e97b,color:#fff
Flux Signature de Pétition
1

Utilisateur consulte une pétition

GET /api/v1/petitions/:id → Affiche détails

↓
2

Clique le bouton "Signer"

Vérification: utilisateur authentifié ? déjà signé ?

↓
3

POST /api/v1/petitions/:id/sign

Crée signature + Incrémente counter

↓
4

Mise à jour en temps réel

Frontend récupère nouveau nombre de signatures

↓
5

Notification et analytics

Email créateur + Log analytics
